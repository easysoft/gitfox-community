# GitFox 初始化安装流程 (init)

本文档描述了执行 `gitfox init` 命令时的交互式初始化工作流。

## 核心流程结构

启动 `init` 命令后，程序会唤起基于 `huh` 框架构建的交互式终端 UI (TUI)。流程被分为以下几个重要阶段：

### 1. 部署模式选择
- **欢迎指引**：打印欢迎横幅。
- **同机部署确认**：首先询问用户 **“是否与禅道服务端安装在同一台机器？”**。这决定了接下来如何收集环境配置信息。

### 2. 信息收集与验证 (兵分两路)

#### A. 同机模式 (Same Machine Flow)
1. **自动提取配置**：用户输入禅道配置文件目录所在路径。程序会实时拦截校验目录有效性，并尝试定位及解析 `$zentaoPath/my.php`。
2. **提取凭证**：自动从 `my.php` 提取数据库链接配置（Host, Port, User, Password, DB Name）。
3. **连通性校验**：实时利用由 PHP 配置拼装出来的 DSN 测试 MySQL 数据库是否畅通。
4. **服务地址输入**：引导用户输入禅道 IP/域名，及选择应用实际要安置的物理工作目录 (Workspace)（程序根据 my.php 上层路径推算了一个推荐默认值）。

#### B. 异机模式 (Different Machine Flow)
1. **人工提写**：引导用户通过逐项表单输入：主机 Host、端口 Port、库名 Name、账户 User，并以密码隐藏模式输入密码。提供主机名校验拦截 Docker 内部未解析名称。
2. **凭据回显**：打印脱敏后的待连接的资产信息摘要。
3. **连通性校验**：实时测试用户录入的数据库连通性。如果失败立即掐断流程重来。
4. **服务地址输入**：引导用户输入禅道 IP/域名，及选择要安置的物理工作目录 (Workspace)（默认获取现有配置）。

### 3. 系统参数组装与校验
1. 自动调用网卡获取当前 Linux 宿主机物理 IP。
2. 从内部模板读取内置系统默认的 `GITFOX_HTTP_PORT`。结合两端组装真正的调用链路。
3. 对用户刚才填写的 ZenTao IP/主机 进行 HTTP 请求真实嗅探，校验服务端 API（例如调取 `/api.php/v1`）是否连通且合法。

### 4. 环境融合与文件写入
1. **覆盖保护检查**：检测将要输出的 Workspace 目录中，是否已经存在 `prod.env` 或二进制产物（`gitfox` / `gitfox.exe`）。如果有，发起醒目的危险覆盖警告并请求许可。
2. **生成环境变量配置**：加载 `configs/prod.env` 里的基准模板并提取合并已有的 `local.env` 用户自定义项。将交互流程中填写的数据库、URL地址热插入更新模板中响应的 Key 处，并将最终成品序列化写盘。
3. **自我复制分发**：当前正在执行 `init` 的二进制文件，会自动分析出自身物理路径，以 Stream 流模式在目标 Workspace 目录复制出一份全功能执行实体。
4. **禅道联动配置下发**：
   - **同机部署**：利用安全正则匹配算法，直接热覆盖宿主机器上禅道的 `my.php` 配置文件，透明化地将当前 GitFox 执行环境的网络入口（IP与端口）注册进去，完成组件总线缝合。
   - **异机部署**：系统由于无法直接穿透远端目录，终端将自动打印一段拼装好具体真实源IP和最终端口的配置代码段落块，提醒用户人工去禅道服务所在服务器黏贴追加。

### 5. 最终摘要与完成
- 提供彩色精美的完成配置清单。
- 在摘要最后抛出对下级命令的**使用指引 (Hint)**：提示用户 `cd` 进入指定目录并运行 `./gitfox start`。

---

> **设计宗旨**: 整个构建流程奉行 Fail-Fast (尽早失败) 和防呆拦截，包括 IP 段校验、多语言支持以及各种网络穿透探测，确保向导完成后一定可以通过 Start 指令直接启动无异常。
