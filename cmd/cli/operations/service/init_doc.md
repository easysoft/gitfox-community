# GitFox 安装与初始化流程 (install / init)

本文档描述了执行 `gitfox install` (一键安装) 或 `gitfox init` (单纯初始化配置) 命令时的终端交互式工作流。

## 核心流程结构

程序目前基于自定义的**轻量级内联终端提示 (Inline Prompt) 系统**。该系统强制显式的 `[Y/N]` 确认（无默认值），并支持优雅的就地错误重试。流程分为以下几个重要阶段：

### 1. 前置依赖巡检 (仅 install 命令适用)
- 对系统的 Git, Docker, Docker Compose 状态与版本进行前置约束校验。如果不符合要求则提前中断。

### 2. 部署模式选择
- **欢迎指引**：打印相关提示或横幅。
- **同机部署确认**：首先询问用户 **“是否与禅道服务端安装在同一台机器？[Y/N]”**。必须明确键入 Y 或 N。这决定了接下来如何收集环境配置信息。

### 3. 信息收集与验证 (兵分两路)

#### A. 同机模式 (Same Machine Flow)
1. **自动提取配置**：用户输入禅道配置文件目录所在路径。程序会实时拦截校验目录有效性，并尝试定位及解析 `$zentaoPath/my.php`。
2. **提取凭证**：自动从 `my.php` 提取数据库链接配置（Host, Port, User, Password, DB Name）。
3. **连通性校验**：实时利用由 PHP 配置拼装出来的 DSN 测试 MySQL 数据库是否畅通。校验失败将即刻拦截。
4. **工作目录选择**：引导用户选择应用实际要安置的物理工作目录 (Workspace)。

#### B. 异机模式 (Different Machine Flow)
1. **人工提写**：引导用户通过逐项表单输入：主机、端口、库名、账户，并以**密码隐藏模式**输入数据库密码。
2. **凭据回显**：打印脱敏后的资产信息摘要（密码用 `***` 遮掩）。
3. **连通性校验**：实时测试用户录入的数据库连通性。如果失败立即掐断流程退出。
4. **工作目录选择**：引导用户选择要安置的物理工作目录 (Workspace)。

### 4. 服务地址嗅探与环境核验
1. 自动调用网卡获取当前宿主机本机 IP。
2. 引导用户独立输入禅道 IP/域名（输入被执行强校验）。
3. 利用组装好的地址进行 HTTP API 实地探测 (例如触发 `/api.php/v1`)。
   - **错误重试机制**：如果握手失败（如网络不通/未响应），会在终端原地打印红色错误，并允许用户**直接重新输入新地址**，避免了填错就要重头来过的糟糕体验。

### 5. 环境融合与安全写盘
1. **防呆备份保护**：检测 Workspace 目录中是否已存在 `prod.env`、`prod.yaml` 或二进制 `gitfox` 实体。若存在则进行安全的 `_bak` 后缀重命名备份。
2. **生成环境变量配置**：加载内置的 `prod.env` / `prod.yaml` 模板。将交互确定的 DSN 链接、URL 地址等热写入其中，保证其余高级配置和原有自定义配置不丢失。
3. **自我裂变分发**：当前启动的程序实体将通过流复制 (Stream)，安全传递并生成一份权限为 `0755` 的全功能二进制拷贝到目标目录。
4. **禅道服务总线注册**：
   - **同机部署**：后台静默正则解析并覆盖目标禅道的 `my.php`，直接打入 `$config->devops->gitfoxURL` 等通讯通道变量。
   - **异机部署**：在屏幕上打印出带有实际 IP 的规范化 PHP 代码片段，提示运维手动到主机上补充配置。

### 6. 最终摘要与启动分流
- 打印完成配置清单（脱敏状态）。
- **指令分流动作**：
   - 经由 `init` 发出的：末尾抛出 **使用指引 (Hint)**，提示用户通过 `cd /path` 和 `./gitfox start` 手动开启守护服务。
   - 经由 `install` 发出的：向导层拦截该提醒，交由 `install` 的上下文自动紧接着去完成注册服务及 `docker compose up` 等后续动作。

---

> **设计宗旨**: 整个向导奉行 Fail-Fast (尽早失败)、安全脱敏、显式确认（拦截回车误触）和无缝就地重试网络探测，确保向导能交出 100% 连通的成果交给下一步后台进行守护调度。
